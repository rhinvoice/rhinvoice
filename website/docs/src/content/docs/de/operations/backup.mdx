Rhinvoice sichert seine ganze Datenbank mit [restic](https://restic.net): **verschlüsselt, dedupliziert und komprimiert**, täglich und kurz nach jedem ausgestellten oder stornierten Dokument, auf ein Ziel Ihrer Wahl (S3, SFTP, Dropbox, Google Drive oder einen Ordner). In der Datenbank steckt alles: Kunden, Artikel, Dokumente, die archivierten PDFs ausgestellter Dokumente, das Logo und die Einstellungen.

## Wann und wie lange

- **Wann:** täglich (standardmässig um 02:00 Uhr, `BACKUP_DAILY_AT`) und etwa zwei Minuten nachdem Dokumente ausgestellt oder storniert wurden (mehrere hintereinander ergeben ein Backup). *Einstellungen → Backup → Jetzt sichern* fordert sofort eines an.
- **Aufbewahrt:** 7 tägliche, 4 wöchentliche, 12 monatliche und **alle jährlichen** Backups. Rechnungen müssen zehn Jahre aufbewahrt werden (Art. 958f OR, GoBD, BAO), jährliche Backups werden deshalb nie gelöscht. Alte Backups werden sonntags entfernt. Dabei wird auch eine Stichprobe von 5 % der Daten geprüft.
- **Nicht gesichert:** eine Installation ohne Firmendaten (eine frische). Ihre leere Datenbank darf nie das neueste Backup werden.
- **Angezeigt:** Die Übersicht warnt, wenn das letzte erfolgreiche Backup älter als 24 Stunden ist oder Backups nicht eingerichtet sind. *Einstellungen → Backup* listet die letzten Backups.

## Einrichten

Wählen Sie ein Ziel, tragen Sie es in `.env` ein (neben `compose.yml`) und starten Sie neu mit `docker compose up -d`.

```dotenv
RESTIC_PASSWORD='a-long-random-password'   # encrypts the backups
RESTIC_REPOSITORY=...                      # see below
```

<Aside type="caution" title="Das Passwort zusätzlich woanders aufbewahren">
Ohne `RESTIC_PASSWORD` kann niemand die Backups wiederherstellen, auch Sie nicht. Bewahren Sie es in einem Passwortmanager oder ausgedruckt im Tresor auf. Erzeugen Sie es mit `openssl rand -hex 32` oder setzen Sie es in einfache Anführungszeichen: Docker Compose würde sonst ein `$` darin verändern.
</Aside>

### S3-kompatibler Speicher

Backblaze B2, Infomaniak Swiss Backup, AWS, Wasabi und andere:

```dotenv
RESTIC_REPOSITORY=s3:https://s3.eu-central-003.backblazeb2.com/my-bucket/rhinvoice
AWS_ACCESS_KEY_ID=...
AWS_SECRET_ACCESS_KEY=...
```

Verwenden Sie einen Schlüssel, der nur auf diesen Bucket zugreifen darf.

### SFTP (NAS, Server)

```dotenv
RESTIC_REPOSITORY=sftp:backup@nas.example:/backups/rhinvoice
```

Der Container braucht den SSH-Schlüssel und den Host-Schlüssel des Servers (`known_hosts`). Binden Sie beide ein, z. B. in einer `compose.override.yml`:

```yaml
services:
  backup:
    volumes:
      - ./ssh:/home/backup/.ssh:ro   # id_ed25519 and known_hosts
```

```bash
ssh-keyscan nas.example > ssh/known_hosts
sudo chown -R 10001 ssh && chmod 700 ssh && chmod 600 ssh/id_ed25519   # the container's user
```

### Dropbox und andere Cloud-Speicher

restic erreicht sie über [rclone](https://rclone.org), das im Backup-Container enthalten ist. Das erste Backup enthält alle archivierten PDFs, spätere nur noch das Geänderte, meist wenige Kilobyte.

<Steps>

1. **Zugriff erlauben**, einmalig, auf einem Rechner mit Webbrowser (es muss nicht der Server sein): rclone 1.75 oder neuer installieren ([rclone.org/downloads](https://rclone.org/downloads/), auf dem Mac `brew install rclone`) und ausführen:

   ```bash
   rclone authorize "dropbox"
   ```

   Melden Sie sich im geöffneten Browser bei Dropbox an und erlauben Sie den Zugriff. Das Terminal zeigt dann ein Token: eine Zeile, die mit `{"access_token":` beginnt.

2. **Das Token dem Backup-Container geben**, auf dem Server, im Rhinvoice-Ordner. `read` hält das Token vom Bildschirm und aus dem Verlauf der Shell fern:

   ```bash
   read -rs TOKEN    # paste the token, press Enter
   docker compose run --rm --no-deps backup rclone config create dropbox dropbox \
     config_refresh_token false token "$TOKEN"
   unset TOKEN
   ```

   Die Konfiguration liegt unverschlüsselt im Volume `backup-rclone`. rclone erneuert den Zugriff dort selbst.

3. **Den Ordner wählen** in `.env` und neu starten (`docker compose up -d`):

   ```dotenv
   RESTIC_REPOSITORY=rclone:dropbox:Rhinvoice-Backup
   ```

4. **Ausprobieren:** Warten Sie, bis `docker compose logs backup` die Zeile `waiting for requests` zeigt, und führen Sie dann `docker compose exec backup rhinvoice-backup backup` aus. Der Ordner `Rhinvoice-Backup` erscheint in Ihrer Dropbox, *Einstellungen → Backup* zeigt das Backup. Beim ersten Start dauert das Anlegen des Repositorys über rclone etwa eine Minute. Bis Version 0.6.0 scheitert ein Backup, das Sie vorher anfordern, mit `config file already exists`, obwohl alles in Ordnung ist.

</Steps>

Die Dropbox-App von rclone darf auf Ihre ganze Dropbox zugreifen. Für Zugriff auf nur einen Ordner legen Sie eine eigene Dropbox-App mit «App folder»-Zugriff an ([rclone.org/dropbox](https://rclone.org/dropbox/#get-your-own-dropbox-app-id)) und ergänzen deren `client_id` und `client_secret` in beiden Befehlen.

**Google Drive** braucht eine eigene Client-ID, weil die gemeinsame von rclone im Lauf von 2026 abgeschaltet wird. Die Schritte stehen auf einer eigenen Seite: [Backup auf Google Drive](/docs/de/operations/backup-google-drive/).

Für andere Anbieter (OneDrive, kDrive und andere WebDAV-Speicher) führen Sie `docker compose run --rm --no-deps backup rclone config` aus, antworten auf die Frage nach dem automatischen Webbrowser mit «No» und folgen der rclone-Anleitung des Anbieters. Benennen Sie das Ziel nach Belieben und verwenden Sie es in `RESTIC_REPOSITORY=rclone:<name>:<folder>`.

### Ein Ordner auf diesem Rechner

Ein iCloud- oder Nextcloud-Ordner, der Ordner der Dropbox-App oder eine USB-Festplatte:

```dotenv
RESTIC_REPOSITORY=/repository
BACKUP_LOCAL_DIR=/Users/me/Library/Mobile Documents/com~apple~CloudDocs/Rhinvoice-Backup
```

Der Container schreibt als Benutzer 10001. Unter Linux machen Sie den Ordner für ihn beschreibbar (`sudo chown 10001 /path/to/folder`). Ohne `BACKUP_LOCAL_DIR` landen die Backups in einem Docker-Volume auf derselben Festplatte. Das schützt vor Fehlern, nicht vor einer defekten Festplatte.

## Prüfen

```bash
docker compose logs backup                            # what the container does
docker compose exec backup rhinvoice-backup snapshots # list the backups
docker compose exec backup rhinvoice-backup check     # verify the repository
docker compose exec backup rhinvoice-backup backup    # back up now
docker compose exec backup rhinvoice-backup rclone lsd dropbox:  # an rclone target is reachable
```

## Wiederherstellen

Wiederherstellen **ersetzt die ganze Datenbank** durch den Stand eines Backups. Es läuft in einer einzigen Transaktion: Schlägt etwas fehl, ändert sich nichts.

```bash
docker compose exec backup rhinvoice-backup snapshots   # pick a snapshot ID
docker compose stop app backup
docker compose run --rm --no-deps backup restore latest # or the ID, e.g. 52365e00
docker compose start app backup
```

Aus dem Quellcode-Ordner: `make restore SNAPSHOT=latest`.

**Auf einem neuen Rechner:** Installieren Sie Rhinvoice wie unter [Installation](/docs/de/getting-started/installation/) beschrieben, mit demselben `RESTIC_REPOSITORY` und `RESTIC_PASSWORD`. Starten Sie zuerst **nur die Datenbank** (`docker compose up -d db`), stellen Sie wie oben wieder her und starten Sie dann alles (`docker compose up -d`).

## Wiederherstellung neben der laufenden Installation ausprobieren

Probieren Sie nach dem Einrichten einmal eine Wiederherstellung aus. Eine zweite Installation in einem eigenen Ordner stellt das neueste Backup wieder her, ohne die erste zu berühren ([mehrere Installationen auf einem Rechner](/docs/de/getting-started/installation/#mehrere-installationen-auf-einem-rechner)). Das Beispiel geht von einer Installation in `~/rhinvoice` mit dem Projektnamen `rhinvoice` aus. Setzen Sie Ihre eigenen Namen ein.

```bash
mkdir ~/rhinvoice-restoretest && cd ~/rhinvoice-restoretest
cp ~/rhinvoice/compose.yml ~/rhinvoice/.env .
# Its own project name and port, and no recurring invoices from the copy.
# On Linux: sed -i 's/…/…/' .env (without the '').
sed -i '' 's/^COMPOSE_PROJECT_NAME=.*/COMPOSE_PROJECT_NAME=rhinvoice-restoretest/; s/^RHINVOICE_PORT=.*/RHINVOICE_PORT=8100/' .env
echo 'RHINVOICE_RECURRING=false' >> .env
grep -E '^(COMPOSE_PROJECT_NAME|RHINVOICE_PORT|RHINVOICE_RECURRING)=' .env   # check all three

docker compose up -d db
# Only with an rclone target (Dropbox, Google Drive …): copy the access into the copy's volume.
docker compose run --rm --no-deps backup rclone version
docker run --rm -v rhinvoice_backup-rclone:/from:ro \
  -v rhinvoice-restoretest_backup-rclone:/to alpine sh -c 'cp -a /from/. /to/'

docker compose run --rm --no-deps backup snapshots
docker compose run --rm --no-deps backup restore latest
docker compose up -d app        # the app only, never the copy's backup container
```

Öffnen Sie `http://localhost:8100`, melden Sie sich an und sehen Sie sich einige Rechnungen an. Versenden Sie nichts aus der Kopie: Die Einstellungen des Mailservers wurden mit allem anderen wiederhergestellt. Danach entfernen Sie die Kopie:

```bash
grep '^COMPOSE_PROJECT_NAME=' .env     # must show rhinvoice-restoretest
docker compose down -v
cd ~ && rm -rf ~/rhinvoice-restoretest
```

<Aside type="caution" title="Der Projektname entscheidet, worauf ein Befehl wirkt">
Ohne geänderten `COMPOSE_PROJECT_NAME` wirken alle Befehle oben, auch `down -v`, auf die echte Installation. Fehlt die Zeile in `.env`, fügen Sie sie hinzu.
</Aside>

- **Starten Sie die App mit Namen.** Ein blosses `docker compose up -d` startet auch den Backup-Container der Kopie. Zwei Installationen, die in dasselbe Repository sichern, würden ihre Backups vermischen. Wollen Sie das wirklich, geben Sie jeder ein eigenes `BACKUP_HOST`.
- **Der rclone-Zugriff liegt pro Projekt** im Volume `<Projekt>_backup-rclone`. Ohne den `cp`-Schritt fehlt er der Kopie. `docker volume ls` listet die Volumes.
- `RHINVOICE_RECURRING=false` verhindert, dass die Kopie die wiederkehrenden Rechnungen der echten Installation schreibt und versendet.
