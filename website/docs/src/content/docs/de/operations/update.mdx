Für ein Update setzen Sie die neue Version in `.env`, holen die Images und starten die Container neu. Die Datenbank wird beim Start automatisch migriert. Lesen Sie vorher das Änderungsprotokoll und machen Sie ein Backup.

## Vor dem Update

- **Lesen Sie das [Änderungsprotokoll](https://github.com/rhinvoice/rhinvoice/blob/main/CHANGELOG.md)** (CHANGELOG, auf Englisch). Rhinvoice folgt Semantic Versioning; vor Version 1.0 können auch Nebenversionen Änderungen enthalten, die nicht rückwärtskompatibel sind. Die Versionen finden Sie unter [GitHub Releases](https://github.com/rhinvoice/rhinvoice/releases).
- **Machen Sie ein Backup**, falls Sie eines eingerichtet haben ([Backup und Wiederherstellen](/docs/de/operations/backup/)):

  ```bash
  docker compose exec backup rhinvoice-backup backup    # back up now
  ```

## Aktualisieren

<Steps>

1. Setzen Sie im Ordner mit `compose.yml` und `.env` in `.env` die Einstellung `RHINVOICE_VERSION` auf die neue Version, z. B. `RHINVOICE_VERSION=0.7.3`.

2. Images holen und neu starten:

   ```bash
   # set RHINVOICE_VERSION in .env to the new version, then
   docker compose pull
   docker compose up -d
   ```

3. Prüfen, ob alles läuft: `docker compose ps` zeigt nach einigen Sekunden «healthy».

</Steps>

Die Datenbank wird beim Start automatisch migriert (`RHINVOICE_RUN_MIGRATIONS=true` in `.env`).

## Feste Version oder latest

`.env` bestimmt, wie Rhinvoice neuen Versionen folgt:

| `RHINVOICE_VERSION` | Verhalten |
|---|---|
| eine Version, z. B. `0.7.3` | fest: ändert sich nur, wenn Sie sie ändern |
| `latest` | folgt jeder neuen Version beim nächsten `docker compose pull` |

Für echte Rechnungen ist eine feste Version die sicherere Wahl: Sie entscheiden, wann Sie aktualisieren, und können vorher das Änderungsprotokoll lesen.

<Aside type="note" title="Ausgestellte Rechnungen bleiben, wie sie sind">
Ein Update ändert nie ausgestellte Dokumente. Sie behalten ihren Inhalt und ihr archiviertes PDF. Eine geänderte Druckvorlage gilt nur für neue PDFs.
</Aside>

## Hinweis auf eine neue Version

Rhinvoice prüft einmal am Tag, ob es eine neue Version gibt. Dann erscheint unten in der Navigation eine Karte mit der neuen Versionsnummer, einem Link zu den Neuerungen und den zwei Schritten für den Server: die Zeile für `.env` und der Befehl, beide zum Kopieren. Dieselbe Information steht in *Über Rhinvoice*, zusammen mit dem Hinweis, ob Sie auf dem neuesten Stand sind. Mit **Nach Updates suchen** fragt Rhinvoice dort sofort nach, statt bis zum nächsten Tag zu warten.

Für die Prüfung lädt Rhinvoice eine kleine, signierte Datei vom neuesten Release auf GitHub. GitHub sieht dabei wie bei jedem Download die Adresse Ihres Servers; Daten Ihrer Installation werden nicht übertragen. Eine Datei, deren Signatur nicht stimmt, wird verworfen. Wer das nicht möchte, schaltet die Prüfung in `.env` ab:

```bash
RHINVOICE_UPDATE_CHECK=false
```

## Testkandidaten ausprobieren

Bevor eine Version freigegeben wird, erscheint sie auf GitHub als Testkandidat (ein Pre-Release mit einem Tag wie `v0.7.4-rc.1`). Normalerweise bietet Rhinvoice Testkandidaten nie an. Um sie auf einer Testinstallation auszuprobieren, setzen Sie in `.env`:

```bash
RHINVOICE_UPDATE_CHANNEL=test
```

Im Programm für Windows und Mac ergänzen Sie in `rhinvoice.json` im Datenordner (siehe [wo Ihre Daten liegen](/docs/de/getting-started/install-desktop/#wo-ihre-daten-liegen)) die Zeile `"update_channel": "test"` und starten Rhinvoice neu. Die Signaturprüfung ist dieselbe wie bei freigegebenen Versionen.

<Aside type="caution">
Testkandidaten sind zum Testen da. Verwenden Sie sie mit einer Kopie Ihrer Daten, nicht für die Rechnungen, die Sie verschicken.
</Aside>

## Welche Version läuft?

Die Version steht unten in der Navigation, neben «by webberz». Ein Klick öffnet *Über Rhinvoice* mit einem Link zu den *Neuerungen*.
