To update Rhinvoice, set the new version in `.env`, pull the images and restart the containers. Database migrations run automatically on start. Before that, read the changelog and make a backup.

## Before you update

- **Read the [changelog](https://github.com/rhinvoice/rhinvoice/blob/main/CHANGELOG.md).** Rhinvoice follows Semantic Versioning; before 1.0, minor versions may contain breaking changes. The versions are listed under [GitHub releases](https://github.com/rhinvoice/rhinvoice/releases).
- **Make a backup**, if you set one up ([Backup and restore](/docs/operations/backup/)):

  ```bash
  docker compose exec backup rhinvoice-backup backup    # back up now
  ```

## Update

<Steps>

1. In the folder with `compose.yml` and `.env`, set `RHINVOICE_VERSION` in `.env` to the new version, e.g. `RHINVOICE_VERSION=0.6.2`.

2. Pull the images and restart:

   ```bash
   # set RHINVOICE_VERSION in .env to the new version, then
   docker compose pull
   docker compose up -d
   ```

3. Check that everything runs: `docker compose ps` shows "healthy" after a few seconds.

</Steps>

Database migrations run automatically on start (`RHINVOICE_RUN_MIGRATIONS=true` in `.env`).

## Pinned version or latest

`.env` decides how Rhinvoice follows new releases:

| `RHINVOICE_VERSION` | Behaviour |
|---|---|
| a version, e.g. `0.6.2` | pinned: changes only when you change it |
| `latest` | follows every release on the next `docker compose pull` |

A pinned version is the safer choice for real invoices: you decide when to update and can read the changelog first.

<Aside type="note" title="Issued invoices stay as they are">
An update never changes issued documents. They keep their content and their archived PDF. A changed print template only applies to new PDFs.
</Aside>

## Notice of a new version

Once a day Rhinvoice checks whether a new version exists. Then a card appears at the foot of the navigation with the new version number, a link to what is new and the two steps for the server: the line for `.env` and the command, both ready to copy. *About Rhinvoice* shows the same, and whether you are up to date.

For the check Rhinvoice downloads a small, signed file from the latest release on GitHub. As with any download, GitHub sees your server's address; no data of your installation is sent. A file whose signature does not match is discarded. To switch the check off, set in `.env`:

```bash
RHINVOICE_UPDATE_CHECK=false
```

## Which version am I running?

The version is shown at the foot of the navigation, next to "by webberz". A click opens *About Rhinvoice*, with a link to *What's new*.
